# Current-build native two-cycle invocation

Invocation V2 selects the current V6 Ergo builder for the local synthetic FED
profile. It is not production-ready. Native composition, two-cycle execution,
recovery and operator acceptance remain separate validation requirements.
The [execution plan](../phases/bridge-execution-plan.md) owns the delivery queue.

## Entry points

The existing parent script accepts `--invocation-v2 --config <config-file>`
after the pinned Node/loader arguments. This selects
`runSubstrateFederatedNativeTwoCycleFromArgumentsV3` in
[`run-substrate-federated-native-two-cycle-v2.ts`](../relayer/src/scripts/run-substrate-federated-native-two-cycle-v2.ts).
The parent supplies the same selector to its worker. The worker's V3 entry
calls the explicit Root V2 API.

The existing `preflight-substrate-federated-native-two-cycle-v1.ts` script also
accepts `--invocation-v2 --config <config-file>` after the pinned Node/loader
arguments. It selects the V2 loader, environment checks and V6 output metadata
checks without consuming the three physical pre-entry scratch homes. Its V1
report format and fourteen false execution/authorization flags remain unchanged.
It does not establish full raw/cache integrity, port availability, custody,
fees or operational admission.

The filenames retain `v2`; the named entry functions are V3. Without the
selector, the existing CLI and named V2 functions retain their V1 invocation
contract. Unknown or repeated selectors are rejected. Configuration content
does not silently select another route.

Use the [native campaign prerequisites](federated-native-two-cycle.md) and
separate operational admission before an execution. The argument vector alone
does not establish source, output, custody, fee or resource admission.

## Configuration contract

The schema is `e2s.substrate-federated-native-two-cycle-invocation.v2` with
numeric `version: 2`. Common Frontier, commit, output and observation fields
retain their existing meanings. Replace the four flat fields
`ergoSourcePath`, `ergoGitExecutablePath`, `ergoJavaExecutablePath` and
`ergoSbtLauncherJarPath` with one `ergoBuild` record. Those legacy fields are
rejected by the V2 loader.

`ergoBuild` contains exactly these 17 fields:

| Fields | Meaning |
|---|---|
| `bridgeRoot`, `sourcePath` | Selected bridge checkout and fresh patched Ergo source |
| `gitExecutablePath`, `javaExecutablePath`, `sbtLauncherJarPath`, `systemRoot` | Local pinned tools and Windows root |
| `mirrorRoot`, `bootRoot` | Selected Maven data and SBT boot data |
| `leveldbRoot`, `leveldbReceiptPath`, `mavenNamespaceRoot`, `v6MavenSourceRoot` | Current V6 dependency inputs and their source lineage |
| `lockSelection` | Exactly `v6-current` |
| `caps`, `maxMembershipBytes` | Explicit generated-output and path-inventory limits |
| `gitHomes`, `resultPath` | Eight create-new Git homes and a separate empty build-result parent |

The nested `bridgeRoot` must identify the common bridge checkout. Git homes
and the result parent must be on D, outside the source parent and separate
from invocation attempt storage. Source, cache, tool and build paths must
satisfy the selected local Windows profile. The loader rejects overlapping
roles and dangling links.

The compiled ceilings are 50,000 generated files, 4,096 directories,
536,870,912 generated bytes and 16,777,216 membership bytes. Per-root limits
and the selected operation's authorization remain binding; a compiled ceiling
does not approve a larger operation budget.

The loader retains the exact original configuration bytes and SHA-256. The
parent captures those bytes unchanged, and the worker reloads them through
the V2 loader. V2 path and tool identities use distinct domains.

## Validation and lifecycle

The parent checks the immutable V2 environment and fresh outputs before WASM
construction, then repeats both immediately before creating the attempt.
The worker checks configuration, parent and WASM bindings, immutable inputs
and freshness before its claim. It dispatches to Root V2 without a V1 fallback.

Each boundary also runs the existing complete V6 source and dependency
pre-entry verifier. This recaptures the patched raw source, Maven mirror,
SBT boot data and LevelDB overlay before attempt creation or Java execution.
The verifier uses a separate create-new Git home under the configured `b0`
home's parent, named `.v6-preentry-parent-before-wasm`,
`.v6-preentry-parent-before-attempt` or `.v6-preentry-worker-before-claim`.
These scratch homes remain separate from the eight actor homes. Retain them
after a failed check; occupied scratch paths reject another entry. Prepare
fresh owned storage instead of removing or reusing a retained scratch home.

After root execution, environment validation checks immutable inputs only:
the builder is expected to have created its target, result and Git homes.
The existing V1 result, transport and diagnostic formats remain bound to the
V2 configuration hash. A result, claimed worker or failed entry does not
permit retry or resume. A future run requires its own fresh selected inputs,
outputs and operational admission.
